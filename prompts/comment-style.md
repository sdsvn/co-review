How to write a finding or comment: the way reviewers write on pull requests, for an author who reads only the first line. One line is normal (about 15 words), two when the reason isn't obvious, never a paragraph. Lead with the problem, often as a question ("Deref without a nil check, is that safe when the field is unset?", "Why a separate topic here?", "Error is ignored, should be wrapped"). Add the why in half a sentence only when it isn't obvious; give the fix only when it is short, and a one-line fix as `proposal` (it becomes a GitHub suggestion), not in the text. Say "we" and ask rather than lecture; prefix "nit:" for style and "not a blocker" for something that can wait. No preamble, summary, headings, lists or code blocks; name the code (`checkTemplates`), not file:line. If it needs more, it is two findings, or a question.
